Workbench v0.6.0 · architecture

How Workbench works

A feature moves through six stages, from the moment you create it to the end of its agent's turn. Workbench hooks into Claude Code at each one, a local Laya model can judge the work along the way, and one observer tells you when any agent needs you.

A feature's lifecycle

Questions and plan approval are always yours. Laya acts only in "on" mode; in shadow mode it shows what it would do. On a narrow screen, scroll the diagrams sideways.

One entry file, many modules

Claude Code follows $ only within the file that receives it, so register.js is the only file that touches it. For each hook call it wraps $ in an adapter, io, and hands that to the handler. Every other module works through io.

The engine also requires atoms to be read in the file that declares them, so the four atoms live in register.js and other modules name them by key: io.read(sessions).

The observer: two inputs, one state

The observer is not one hook. Agents in your session are heard through events; agents in Workbench Web through the poll. Both write each feature's record, tagged with its runner, into the same sessions atom, and everything you see is drawn from that atom.

A poll rewrites the web records and keeps the in-session ones, inside one atom update, so a hook that writes in between is never lost.

Turning on Laya

Laya is an open source decision model that runs inside Workbench Web, on your machine, with no key. It answers typed questions and never writes text: every message comes from your standards.

// .claude/workbench.json
{ "decisions": { "provider": "laya", "mode": "shadow" } }

// .claude/workbench-standards.json: exact rules, and sentences Laya judges
{
  "rules":  [{ "id": "site-plain-html", "tools": ["Write", "Edit"], "field": "file_path",
               "match": "(^|/)site/", "unless": "\\.(html|css|md)$",
               "message": "site/ is plain HTML and CSS. Put this in an .html or .css file." }],
  "judged": [{ "id": "site-no-frameworks", "text": "site/ stays plain HTML and CSS: no frameworks or bundlers.",
               "appliesTo": ["edit", "plan"] }]
}
  • Shadow first. Every judgment shows as a ◆ Laya line and nothing acts. When its calls match yours, set "mode": "on".
  • Rules before judgment. Exact rules (paths, flags, key formats) are checked in code; Laya only judges the sentences.
  • Off until you opt in. The weights are about 1.6 GB, so the repo ships with "provider": "off"; ./setup.sh --laya downloads them once and switches it on.
  • Or hosted. TypeSafe's hosted Jev speaks the same protocol, so it can replace Laya with "provider": "http".
