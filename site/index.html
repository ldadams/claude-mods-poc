Work several features at once.

Start an agent on every feature, in your Claude Code session or in Workbench Web. One observer tells you when any of them needs you, and a local model holds the work to your standards.

How it works

  1. Describe the work. A feature is a JSON file in .claude/features/, shared through git, with its own context: files, commands, URLs, notes, MCP calls. Or pull one from a Jira story or a GitHub issue.
  2. Start agents. Each runs where its feature says: as a subagent of your session, or as a Workbench Web session you can also follow in the browser.
  3. Answer when asked. Questions and plans reach you in the pane, the status line and a notification; n takes you to the next one.
  4. Let Laya check the work. Plan first or just do it, edits against your standards, plans, and claims at the end of a turn. See the lifecycle

What's in the box

Features and experiences

Units of work next to your code, grouped into experiences whose shared context reaches every brief. Pull them from Jira epics and stories or GitHub issues. Remotes

Two runners

In your session for quick work, nothing else to start. In Workbench Web for longer work that outlives your terminal and can plan first.

One observer

Hooks hear your session's agents, a poll hears Workbench Web's. One list, one status line, one set of notifications.

Decisions with Laya

A local decision model judges the work at each stage and sends problems back to Claude with what to fix. Shadow mode first. Turn it on

Plan first

Per experience, per feature, or as Laya suggests: the agent plans, you approve the plan card, and it builds in your usual mode.

In the browser

Workbench Web shows the same sessions as the pane, with full transcripts and cards. Start in one, answer in the other.

Try it

$ ./setup.sh                        # Node 20+, Claude Code; add --laya for decisions
$ node workbench-web/server.mjs .   # http://localhost:4477, these docs at /docs/
$ claude --plugin-dir ./workbench   # in a second terminal

/workbench                          # the pane: n, s, o, p, r, w
/feature new Checkout redesign
/ctx add file src/checkout/Cart.tsx
/feature start

Or open the browser's Remote tab and pull a mock Jira story or GitHub issue. Commands: /workbench, /feature, /experience, /ctx, /workflow; each prints its usage with no arguments. Tested against Claude Code v2.1.296.

FAQ

Where is agent state kept?

Never in the feature files, so a commit never carries one person's run status. In-session agents live and end with your Claude Code session; Workbench Web sessions are saved per user and resume after a restart.

Does Laya send my code anywhere?

No. It runs inside Workbench Web on your machine, with no key. Pointing Workbench at TypeSafe's hosted Jev instead does send what it judges to that service.
